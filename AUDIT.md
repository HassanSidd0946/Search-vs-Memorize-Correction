## Q1 — Exact input tensor to the temporal branch

```
x_signal : (B, C=62, T=251), float32
```
- **B**: batch size (trials).
- **C=62**: EEG channels (61 scalp + 1 EOG per the ds005189 channel spec — see F6; not separately excluded).
- **T=251**: samples at `SFREQ=250 Hz` over the epoch window **−0.2 s to +0.8 s** relative to stimulus onset (1.0 s span, 251 samples inclusive).
- This is the **EA-whitened, z-scored raw signal** (`X_k_aligned` / `X_train28_aligned`), *not* a spectrogram or any other transform — whitening (`W`) is a per-channel linear map applied identically across all timesteps (`apply_ea_whitening_signal`, `run_step4_condition4_asymmetric_mamba.py:206–207`).
- Inside the branch: `x_signal.transpose(1,2)` → `(B,T,C)` → `Linear(62→16)` → `(B,T,16)` → N_LAYERS=1 `SelectiveSSMBlock` → `LayerNorm` → mean-pool over T → `(B,16)`.
- File:line — `run_step4_condition4_asymmetric_mamba.py:302–324` (`MambaTemporalBranch`).

## Q2 — Loss / optimizer / gradient path for the Mamba branch

The temporal branch is trained in a **separate, earlier stage** from the classifier that ultimately makes the LOSO prediction — it is **not** end-to-end with the final calibrated classifier.

1. `TemporalOnlyModel` = `MambaTemporalBranch` + a throwaway `nn.Linear(16,2)` classifier head (`:326–341`).
2. Trained per-fold on the 28-subject training pool only (90/10 internal stratified split for early-stopping validation), `nn.CrossEntropyLoss()`, `AdamW(lr=1e-3, weight_decay=1e-2)`, `CosineAnnealingLR(T_max=30)`, gradient clip norm 1.0, early stop patience 8 on validation loss (`:453–488`).
3. Best-validation-loss checkpoint reloaded, then **every parameter is frozen** (`requires_grad=False`, `:484–487`) and the model is set to `eval()`.
4. 16-dim embeddings extracted with `@torch.no_grad()` (`extract_temporal_features`, `:382–391`) for both the 28-subject pool and the held-out subject.
5. These frozen embeddings are concatenated **at the NumPy level** with the raw 1953-dim spatial tangent vector (`:493–495`) — no gradient ever flows between the two branches, and no gradient flows from the final classifier back into the Mamba weights at all.
6. The fused 1969-dim vector then goes through `StandardScaler → PCA(35) → shrinkage-blended LogisticRegression` (classical, non-differentiable) — this is the classifier whose accuracy is reported.

**In one sentence:** the Mamba branch is pretrained end-to-end against its own private classification head and frozen; the reported LOSO accuracy comes from a completely separate downstream linear-calibration stage that only ever sees the frozen embedding, never a gradient.

## Q3 — Is normalisation applied between the tangent vector and PCA?

**Yes**, but not in a way that neutralizes the dimensionality imbalance the reviewer is worried about (F11). `run_step4_condition4_asymmetric_mamba.py:503–506`:
```python
scaler = StandardScaler()
feat_train28_z = scaler.fit_transform(feat_train28)   # fit on 28-subject pool only
feat_cal_z = scaler.transform(feat_cal)
feat_test_z = scaler.transform(feat_test)
```
This is a **single joint scaler fit on the concatenated 1969-dim vector**, standardizing each of the 1969 *individual feature columns* to unit variance — it is not a *per-block* scaler that equalizes the spatial block's and temporal block's total contribution to the variance budget. After this scaling, the post-scaling covariance trace is exactly 1969 (each column contributes 1), and the 16 temporal columns can therefore contribute at most 16/1969 ≈ 0.81% of the total variance PCA is maximizing over, regardless of how informative they are per-dimension. **This is a real, verifiable mechanism for PCA(35) to systematically under-select temporal directions** — it is a milder, more precise version of the reviewer's claim ("no normalisation at all" is not accurate; "no *block-level* normalisation" is). Same code, same issue, in `run_step4_matched_spatial_control.py:204–207` — though that script has no temporal block to lose, so it's not affected in practice.

## Q4 — Pooled vs. per-subject EA reference

**Pooled**, confirmed directly in both current production scripts. `fit_ea_whitening` (`run_step4_condition4_asymmetric_mamba.py:201–204`, identical in `run_step4_matched_spatial_control.py:110–113`):
```python
def fit_ea_whitening(X_train28, shrinkage=COV_SHRINKAGE):
    covs = trial_covariances(X_train28, shrinkage)
    _, W = matrix_sqrt_inv_sqrt(covs.mean(axis=0))   # ONE mean over ALL 28 subjects pooled
    return W
```
Called once per fold as `W = fit_ea_whitening(X_train28_z)` (`:444`), where `X_train28_z` is every trial from all 28 training subjects pooled together — a single global covariance mean, not 28 per-subject means. The **same** `W` is then applied to the held-out test subject (`apply_ea_whitening_signal(X_k_z, W)`, `:446`) — i.e. the test subject is whitened using a reference derived entirely from other people's data, not their own. This exactly matches the bug F3 describes and directly contradicts the mechanism in He & Wu (2020)/Kobler et al. (2022), where each subject (including the test subject) is centered using their *own* reference. This is the single highest-confidence, most consequential finding of Phase 0.

## Phase 0.5 — Deep-Dive Investigation (Gate 0 rejected; read-only, no code/LaTeX changes)

### Priority 1 — Can the memory framing be rescued?

**Yes, partially — but not as "true vs. false memory."** ds005189 has a genuine two-phase design: an **Encode** phase (`sub-XX_task-SearchSupRecFamEncode_beh.tsv`, 50 Search + 50 Memorization trials/subject) and a separate **Test/retrieval** phase (`sub-XX_task-SearchSupRecFamTest_beh.tsv`, 300 trials/subject: 100 `Target` [studied items], 50 `Distractor`, 150 `New (Lure)`), each row carrying a remember/know/new judgment (`rk_judg`) plus confidence (`conf`).

**Linking key confirmed:** `(scene, obj)` — the scene name and object label — uniquely identifies each studied item across the two files. Verified on 6 subjects (sub-01, 02, 03, 04, 05, 09): **100/100 encoding trials matched a `Target` row in the Test file, 0 unmatched, 0 key collisions, in every subject checked.** This is a clean, reproducible, dataset-wide linkage, not a sub-01 fluke.

**Per-subject subsequent-memory (Remember/Know = hit, New = forgotten) outcome, split by encoding condition:**

| Subject | Search: R/K/New | Search forgotten % | Memorization: R/K/New | Memorization forgotten % |
|---|---|---|---|---|
| sub-01 | 40/4/6 | 12% | 35/6/9 | 18% |
| sub-02 | 44/6/0 | 0% | 37/10/3 | 6% |
| sub-03 | 49/0/1 | 2% | 36/5/9 | 18% |
| sub-04 | 47/0/3 | 6% | 40/3/7 | 14% |
| sub-05 | 38/8/4 | 8% | 29/12/9 | 18% |
| sub-09 | 29/18/3 | 6% | 29/16/5 | 10% |

**Implication:** a legitimate "subsequently remembered vs. subsequently forgotten" (Dm-effect / subsequent-memory-effect) relabeling is possible and would be a real, citable cognitive-neuroscience contrast — but it is a fundamentally different and much harder problem than what's currently implemented:
- It is **not** the DRM-style true/false-memory paradigm the manuscript currently claims (that would require decoding hit vs. false-alarm-to-lure responses, which the current pipeline never touches).
- Class balance would be **severely skewed** (~82–100% remembered vs. ~0–18% forgotten per subject/condition) — the opposite of the current pipeline's clean 50/50 Search-vs-Memorize split. A handful of "forgotten" trials per subject (0–9) is too few for reliable within-subject decoding; only a pooled, heavily class-weighted, or leave-several-subjects-out design could plausibly work, and it would need the F13 statistics machinery from day one.
- This is a genuine **candidate reframing**, not a drop-in fix. It would require a new epoch-labeling script (join Encode+Test by `(scene,obj)`), a new class-imbalance strategy, and materially different claims than "true/false memory." Recommend treating this as an optional, clearly-scoped Phase-2 extension (new Condition) rather than a substitute for the existing Search-vs-Memorize (incidental vs. intentional encoding) result — the latter remains valid on its own terms and should be the primary framing regardless.

### Priority 2 — Design confound check (blocked vs. interleaved)

**Confirmed BLOCKED, not interleaved**, from raw `.vmrk` marker analysis (sub-01): of 410 stimulus events, there is exactly **one** transition between the Search(1x)-code family and Memorize(2x)-code family (205 events each side, transition at event #205). Search markers span **229.1s–1238.0s** (~16.8 min), then a ~6.7 min gap, then Memorize markers span **1642.7s–2462.4s** (~13.7 min) to the end of the ~41-minute session. **Every Class-0 trial precedes every Class-1 trial in time, for every subject** — this is a real, unavoidable within-session confound: class is perfectly collinear with time-in-session (fatigue, vigilance decline, electrode-impedance drift, circadian state).

**Block order IS counterbalanced across subjects** (checked first-event-family for 10 subjects via `.vmrk` files: sub-02,04,10,20,30 start with Memorize; sub-03,05,09,15,25 start with Search) — the pattern is a clean **odd-subject-number → Search-first, even-subject-number → Memorize-first** ABAB counterbalance. This mitigates the confound at the *population* level for a LOSO design (no systematic population-wide bias in which class gets "early-session" advantage), but does **not** remove it at the *within-subject* level, and does not rule out the model partially learning session-drift signatures that happen to correlate with class within each subject even if the direction differs by parity. Recommend explicit disclosure in Limitations and, if time permits, a control analysis (e.g., decode using only mid-block trials, or regress out a linear time-in-session term) — logged as a candidate addition to F-LEAK's scope, not implemented here.

### Priority 3 — Ocular-artifact exposure assessment

**(a) EOG channels:** the BIDS sidecar (`sub-01_task-SearchSupRecFam_eeg.json`) declares `"EEGChannelCount": 61, "EOGChannelCount": 1` (62 total), but the actual `.vhdr` channel list (`[Channel Infos]`) enumerates **62 channels, all standard 10-10 scalp names** (Fp1…AF8) — **no channel is named or typed as EOG anywhere in the raw file**. This is a metadata/data inconsistency in the source dataset itself: either the sidecar's channel-count split is stale/wrong, or no dedicated EOG channel was ever exported. Net effect for this pipeline: **there is no distinguishable EOG channel to exclude, reject on, or regress out** — the topoplot feature file's 62-channel list (`topoplot_channel_power_features.json`) matches the raw file's 62 channels exactly, meaning all 62, including the most eye-adjacent ones (Fp1, Fp2, AF7, AF8), are fed into the spatial covariance/tangent-space features as ordinary EEG.

**(b) Frontal/frontopolar channels in the montage (24/62 ≈ 39% of all channels):** Frontopolar: Fp1, Fp2, AF7, AF3, AFz, AF4, AF8 (7). Frontal: F7, F5, F3, F1, Fz, F2, F4, F6, F8 (9). Fronto-central: FC5, FC3, FC1, FCz, FC2, FC4, FC6 (7). Fronto-temporal: FT9, FT7, FT8, FT10 (4).

### F-JOINT — two-stage non-joint training misrepresented as end-to-end dual-branch (Phase 0.5 Priority 5)

Formalizing the Q2 finding (previously narrative-only) as a named, tracked defect:

**(a) Correctness defect — manuscript/Fig. 2 misrepresentation.** `run_step4_condition4_asymmetric_mamba.py` trains the temporal Mamba branch **standalone**, against its own private classifier head (`TemporalOnlyModel`, its own `nn.Linear(16,2)`, `CrossEntropyLoss`, `AdamW`, `CosineAnnealingLR`, early-stopped independently — lines ~440–487), then **freezes it** (`requires_grad=False`) before extracting its 16-D features and concatenating them with the raw 1953-D spatial tangent vector at the **NumPy level** (lines 493–495) — outside any autograd graph. **No gradient ever flows jointly between the two branches, and no gradient ever flows from the final classifier back into either branch.** The manuscript's Fig. 2 and accompanying prose describe this as a single end-to-end dual-branch network trained jointly on the fused objective. That description is factually wrong about this codebase's actual training procedure. This is logged as a **Tier-1 correctness defect, same severity class as F11** (near-identity-passthrough) — both are cases where the paper's account of *what the model does* diverges from what the code actually does.

**(b) Architectural-hypothesis critique — redundant, not complementary, by construction.** Because the temporal branch is optimized standalone to be individually predictive of the same binary label the spatial branch already predicts well, its 16-D output is trained to be **redundant with** the spatial tangent features, not **complementary** to them — there is no mechanism in this training procedure that could ever push the temporal branch to learn something the spatial branch is missing, since the temporal branch never sees the spatial branch's errors or residual signal during its own training. This is the direct mechanistic explanation for why the matched-control ablation (see memory: Condition 4 asymmetric fusion, `run_step4_matched_spatial_control.py`, 70.78% vs. 71.28%, Wilcoxon p=0.92) found the Mamba branch's contribution statistically indistinguishable from zero — the architecture, as trained, was never given a reason to add anything. **F11's per-block-scaling fix (giving the temporal branch a fairer share of PCA's variance budget) cannot fix this** — it only affects how much of an already-redundant signal survives into the final feature vector; it cannot make a standalone-trained branch complementary after the fact.

**(c) Three candidate fixes (not implemented — Phase 0.5 is read-only), with cost estimates:**

| Candidate fix | Description | Est. implementation cost | Est. re-run cost |
|---|---|---|---|
| **1. Joint end-to-end training** | Remove the two-stage split entirely: build a single `nn.Module` containing both branches + fusion + classifier head, backprop the final cross-entropy loss through the whole graph in one optimizer loop. Requires re-deriving the spatial branch as a differentiable op (currently the EA/tangent-space step is NumPy/scikit-learn, not PyTorch) or wrapping it as a fixed (non-learned) differentiable feature extractor feeding a learned fusion+classifier on top of both branches. | **Medium-High** — the spatial pipeline (EA whitening, Log-Euclidean tangent map) would need a PyTorch reimplementation or a frozen-features-in/learned-fusion-out compromise; several days of engineering, higher regression risk since it touches the best-performing branch's math | Full 29-fold LOSO ×seeds: same order as F3/F11 (hours, CPU/GPU mixed) |
| **2. Residual training of the temporal branch on spatial-model errors** | Keep the spatial branch's tangent features fixed/pretrained (as now), but train the temporal branch's loss as a function of the *spatial model's residual errors* (e.g., train on a boosting-style residual target, or restrict the temporal branch's training subset to spatial-model misclassifications) so it is explicitly optimized to be complementary rather than independently predictive. | **Medium** — requires a first pass to get spatial-branch per-trial predictions/margins, then a second training loop with a residual objective; no need to touch the spatial branch's math | Two-pass LOSO: spatial fold (existing, cheap) + temporal-on-residuals fold; roughly 1.5–2× current Condition 4 wall time |
| **3. Jointly-trained gated/cross-attention fusion** | Replace the frozen-concat fusion with a small learned gating or cross-attention module that takes both branches' (still separately pretrained, but now *unfrozen during fusion-stage training*) representations and learns how to weight/combine them against the final label, with gradients flowing back into both branches during this stage. | **Medium** — a new fusion module (a few dozen lines: gate MLP or single-head cross-attention) plus a second fine-tuning stage with both branches unfrozen; more principled than fix 2 but more hyperparameters (gate architecture, unfreezing schedule, learning-rate ratios) to get right | Fine-tuning stage adds a modest fraction of current temporal-branch training cost per fold; full LOSO re-run needed since fusion changes are not separable from the accuracy claim |

**Recommendation (not a decision — flagging for Gate 0/1 scoping):** fix 1 is the methodologically cleanest and the only one that fully resolves (a) the correctness defect, since it makes Fig. 2's "joint dual-branch" description literally true; fixes 2 and 3 are cheaper but only partially resolve (a) (the branches still aren't trained end-to-end from scratch) even though they would meaningfully address (b). Given F3 (pooled EA) and F11 (fusion variance) are already both marked **High risk / likely result-changing**, and F-JOINT's fix 1 touches the same code paths, there may be an efficiency argument for sequencing F3 → F11 → F-JOINT-fix-1 as a single combined re-architecture pass rather than three separate re-runs — but that is a Phase 1/2 scoping decision, not something to act on here.

## Phase 1 — F-STIM Audit Results (2026-08-18, interpretation corrected 2026-08-18 per Gate 1 rejection)

Per D1/F-STIM: computed the `(scene, obj)` stimulus-set overlap between Search and Memorize encoding blocks, per subject and pooled, using every subject's `*_task-SearchSupRecFamEncode_beh.tsv` (all 30 downloaded fresh via `openneuro-py`, beh-only include pattern — cheap, no EEG binaries fetched). Script: `scripts/compute_stim_overlap.py`; full output: `results_stim_overlap.json`. Follow-up analysis (parts (a)/(b) below): `scripts/stim_parity_and_balance_check.py`; full output: `results_stim_parity_and_balance_check.json`.

**Result:**

| Level | Search∩Memorize overlap | Raw fact |
|---|---|---|
| **Within-subject** (every one of 30 subjects individually) | **Jaccard = 0.0000, 0 overlapping stimuli** — 50 unique Search scene/obj pairs and 50 unique Memorize scene/obj pairs, always fully disjoint, with zero exceptions across all 30 subjects (min = max = mean = 0.0) | Within any single subject's session, Search and Memorize trials never show the same picture twice. |
| **Pooled across all subjects** (n=29 EEG-analysis population, and separately n=30 full protocol) | **Jaccard = 1.0000, 100/100 stimuli overlap** — the same 100 (scene,obj) pairs appear in the pooled Search set and the pooled Memorize set | The experiment reuses the identical fixed set of 100 scene/object stimuli across the whole subject pool, but **counterbalances which task each stimulus is assigned to on a per-subject basis**. |

**Corrected interpretation (the original 2026-08-18 write-up understated the confound — do not repeat the error):** the within-subject fact above is not neutral. **Within any single subject, class (Search vs. Memorize) is PERFECTLY confounded with stimulus identity** — every trial's task label is fully determined by which 50 pictures that subject happened to see in which block, since the two 50-item sets never overlap. A within-subject classifier (or any mechanism sensitive to stimulus identity) could achieve perfect within-subject task decoding by memorizing "picture X = Search" for that subject's specific assignment, with zero cognitive content required. **What defuses this is exclusively the cross-subject counterbalancing**, not the within-subject disjointness: because a given stimulus is assigned to Search for some subjects and Memorize for others, a classifier trained under strict LOSO on 28 subjects cannot learn a fixed stimulus-identity-to-label mapping that transfers to the 29th held-out subject — that mapping is inconsistent across the training pool by construction. The confound is real at the within-subject level and is neutralized only at the population/LOSO level, and only insofar as the counterbalancing is actually well-mixed (see part (b) below — it is not perfectly item-by-item balanced). This should be stated in Methods with both halves of the argument explicit: the confound exists, and here specifically is the design property that prevents it from being exploitable under LOSO.

**(a) Is stimulus-to-task assignment the same variable as block-order parity, or crossed independently?** Determined empirically (`scripts/stim_parity_and_balance_check.py`, using subject-number parity as the established odd→Search-first/even→Memorize-first proxy from Phase 0.5 Priority 2 / D2): across all 30 subjects there are **21 distinct Search-set partitions** — the stimulus-to-task assignment is close to individually randomized per subject, not a small number of shared counterbalance lists. Of the 6 partitions shared by more than one subject, **5 contain a mix of odd- and even-numbered subjects**. **Conclusion: CROSSED / INDEPENDENT, not the same variable.** Block order (which task comes first in time) and stimulus assignment (which pictures go in which task) are independently (near-)randomized per subject. **This means F-PARITY's block-order control does NOT also cover the stimulus-identity confound** — they are two separate confound axes, each requiring its own control, and F-STIM's cross-subject-counterbalancing argument is the only control currently addressing the stimulus-identity axis (no separate stimulus-set-split control is implemented; noting this as a residual gap rather than silently assuming F-PARITY covers it).

**(b) Actual counterbalancing balance at n=29, and residual imbalance:** pooled across all 100 canonical stimuli at n=29, the **mean per-stimulus Search-assignment fraction is exactly 0.5000** — aggregate balance is exact. But **per-stimulus balance is not uniform**: individual stimuli range from **7/29 (24.1%)** to **22/29 (75.9%)** of subjects assigning them to Search, distributed symmetrically in complementary pairs (e.g., 10 stimuli at 7/29-Search pair with 10 stimuli at 22/29-Search, summing to 29 — consistent with a handful of underlying counterbalance-list templates combined across subjects rather than a single per-item 50/50 rule). **This is the honest, quantitative counterbalancing-balance number**: exact in aggregate, imperfect per item. Practical consequence: the LOSO-pool-level argument in the corrected interpretation above holds on average, but for the minority of stimuli near the 24–76% extremes, a modest residual stimulus-identity signal could still leak into training-pool-level statistics (e.g., regularization/PCA components that key off popular high-frequency stimulus/task pairings) even though no single stimulus-to-label mapping is fully consistent across the pool. This residual should be disclosed, not treated as fully resolved.

**Limitations disclosure (moved from "out of scope," now recommended for the manuscript's Limitations section):** the cross-subject-counterbalancing argument above rules out an *exact*, *consistent* stimulus-identity shortcut, but it does not rule out *lower-level image statistics correlated with task-assignment* — e.g., if a given subject's Search-assigned images happened to differ systematically in luminance/contrast/complexity from their Memorize-assigned images, and if that image-level bias is itself correlated with the residual per-stimulus imbalance found in (b), a weak, indirect image-statistics confound could survive the counterbalancing argument. This has **not** been analyzed (would require an image-statistics pass over the stimulus set itself) and should be stated in Limitations explicitly alongside the counterbalancing argument that motivates why it is expected to be a small residual risk rather than a first-order confound: aggregate balance is exact (part b), and 21 near-unique per-subject partitions (part a) mean no single image-statistic bias could be shared by more than a handful of subjects at once.

Cross-reference: this is a separate confound axis from F-PARITY's block-order/session-position control (see (a) above) and from F-OCULAR's artifact controls — all three should be reported together in Methods/Limitations as the three independent confound checks performed, not conflated into one.

## Other Unlisted Findings (not fixed, logged per Rule 7)

1. **Zero artifact rejection** (`reject=None`) across all 9,869+ epochs, no ICA, no channel-level quality control. Should be disclosed as a Limitation (F16) regardless of whether it's "fixed." **No EOG channel is even available to regress against** (Phase 0.5 Priority 3(a)) — the BIDS sidecar's declared `EOGChannelCount: 1` does not correspond to any actually-named channel in the raw `.vhdr` files, so EOG regression is not merely skipped, it is currently infeasible with the exported channel set.
2. **Subject exclusion, now fully documented (Phase 0.5 Priority 4):** dataset has 30 raw participants; pipeline runs on 29. Root cause confirmed by direct reproduction: sub-09's `.eeg` binary file is truncated to 109.8 s (of an intended ~41.5 min session) while its `.vmrk` marker file references the full session, leaving zero events inside the available data range. Not a pipeline bug — a source-data export truncation. See Phase 0.5 §Priority 4 above for the full evidence trail and recommended Methods-section wording.
3. **File/header-name drift**: `run_step4_condition4_dualbranch_mamba.py`'s internal header names it `run_step4_condition4_spatial_only_ablation.py` — the file was repurposed without updating its own comments. Cosmetic, but worth a mention since it's what caused the D_MODEL/D_SPATIAL confusion above; future readers (human or agent) will make the same mistake.
4. **Most "current" scripts are untracked in git** (`run_step4_condition4_asymmetric_mamba.py`, `run_step4_matched_spatial_control.py`, all `results_*.json`, `PAPER/`, `Diagrams/`). The one existing commit (`ee9eaae2`) is a single bulk "All Scripted Uploaded" dump with no incremental history — meaning **no fine-grained git archaeology is possible** for anything before this audit. Going forward, Phase 1 commits (per Rule 4) will be the first real history this repo has.
5. **Covariance estimation T/n ratio ≈ 4.05 (Phase 0.5 Priority 6):** each trial epoch has T=251 time samples (−0.2s to +0.8s @ 250 Hz) and n=62 channels, giving a samples-per-channel ratio of only **251/62 ≈ 4.05**. Standard guidance for well-conditioned sample covariance estimation wants T/n ≳ 10 (ideally ≫); at T/n≈4, the raw per-trial sample covariance is severely rank-deficient/ill-conditioned before any shrinkage is applied, meaning the 10–15% shrinkage values used throughout this pipeline are doing heavy structural lifting (not just light regularization) and should be explicitly justified/reported as such rather than treated as a minor hyperparameter — worth an explicit sentence in Methods/Limitations, and a candidate for a shrinkage-sensitivity sweep alongside F9.
6. **Feature dimensionality vs. sample size (Phase 0.5 Priority 6):** the raw Log-Euclidean tangent vector is 1953-D (62×63/2), fused to ~1969-D with the temporal branch, against ~9,869 total trials (~5,805/class after the balancing in `topoplot_channel_power_features.json`) — a features-to-trials ratio of roughly 1:5. While PCA(35) does most of the real dimensionality reduction before the final classifier, the *tangent-vectorization and per-fold whitening/PCA-fitting steps themselves* operate in the full 1953–1969-D space using only the 28 training subjects' trials each fold, which is a substantially smaller effective sample for covariance-structure estimation than the raw trial count suggests once you account for per-subject correlation (trials within a subject are not independent draws for this purpose). Should be disclosed as a Limitation alongside item 5.
